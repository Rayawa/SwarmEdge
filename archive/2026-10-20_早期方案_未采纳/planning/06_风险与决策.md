# 风险与决策登记

这份登记只覆盖与本项目选题和实施直接相关的问题；不是已发现故障列表。

| 风险 | 早期信号 | 降低方式 | 决策点 |
| --- | --- | --- | --- |
| 没有实际问题 | 使用者说单机/摄像头足够 | 用流程和替代方案验证 | G1转为研究平台或停止应用立项 |
| 重复已有工作 | 强基线/近邻已覆盖贡献 | 核对P07/P14和专利线索 | G2收敛差异，不承诺专利 |
| 节点不够轻 | 电池/相机/无线体积占主导 | 报整机尺寸和功率，不报裸板 | 单板门槛 |
| NPU增加负担 | 转换失败、召回退化、CPU筛选已够 | 保留无NPU基线 | 单板门槛 |
| 定位/机械喧宾夺主 | 大量时间消耗在导航和打滑 | 已知地图/固定路线先控变量 | G3不同时自研SLAM与底盘 |
| 主机/链路单点依赖 | 掉线后持续执行旧指令 | 本地租约、停止、版本拒绝 | 地面实验前 |
| 过滤造成漏检/饥饿 | 少上传但任务召回下降 | 保底采样与最差节点服务 | G2/G4 |
| 只有最好结果 | 阈值随结果改、只统计成功帧 | 冻结种子/排除规则/全失败计数 | 实验预注册 |
| 多机维护超预算 | 充电、标定、维修占用显著 | 从2—3台起、整机备用预算 | 扩容评审 |
| 旧软件适配 | ROS2swarm/板SDK版本不兼容 | 参考思想，不强搬旧栈 | 环境冻结 |
| 没有数据追溯 | 时间戳不统一、日志缺ID | 原始日志和时钟误差一起存 | 所有实验 |
| 角色未分配 | 多条线无人负责 | 肖晓和确认首两周角色与交付 | 启动会 |
| 昇腾+OpenHarmony 无 BSP | 板厂无法提供 7.0/API 26 驱动或 CANN | 首期按双底座，主机走 openEuler；签约前书面确认 | P0/P1 门槛 |
| 开放词汇模型转换失败 | ATC 算子报错、精度下降、310B 未验证 | 先做单板 P2；退到 YOLOv8+CLIP 两段，重模型只放主机 | P2 门槛 |
| 全昇腾成本/功耗失控 | 10 台整机约 2.2—4.3 万元、节点侧 100—200 W | 异构分工，昇腾限 1—2 台复核节点＋1 主机 | 预算评审 |
| OpenHarmony 26 生态滞后 | API 26 设备占比低、相机/Wi-Fi 驱动缺 | 开发用 API 24 或 M-Robots，申报写 26 目标 | P0 门槛 |
| 异构角色无人维护 | 侦察/复核/中继配置漂移、日志不一致 | 角色镜像化、统一版本清单与自检 | 每次实验 |
| 紧凑语义基线打平 | 节点特征或小检测已足够，集中式无增益 | 预注册 B6/B7；打平则改任务或改平台论文 | G2 |
