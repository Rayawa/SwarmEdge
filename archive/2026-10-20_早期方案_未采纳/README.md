## 当前决定

- 个体保留电机闭环、急停/看门狗和必要的局部执行；主要语义推理、任务分配集中在局域网主机。
- 集群采用异构分工：多数无 NPU 的侦察节点、1—2 台昇腾复核节点、1 台集中主机；不要求每台都配 NPU。
- 目标架构是端边云统一 OpenHarmony 26；首期机器人侧用 OpenHarmony 7.0／M-Robots，主机侧用昇腾 CANN，统一底座待厂商 BSP 可用后再迁移。
- 首轮先用已知地图、固定路线或外部定位，避免同时承担SLAM、机械设计、全栈控制和新通信算法。
- 场景从“人工布置的室内目标搜索与复核”起步。它是研究验证场景，商业/实际使用需求仍需访谈证明。
- 首要候选贡献是**角色、观测形态与推理档位在共享上行和主机队列约束下的联合决策**。不把“使用ROS2”“选择性通信”“主机卸载”“普通QoS设置”“国产化底座”单独称为创新。
- 先验证1主机+2—3个节点，6/10节点通过回放和进程扩展做压力测试，再决定实机扩容。
- 昇腾只放在复核节点与主机；侦察节点不配 NPU，把“节点侧 NPU 门控”保留为对照项。
- 无实测支持时，吞吐、续航、准确率和节省比例均不作承诺。

## 可复算材料

无需安装第三方依赖：

```bash
python3 tools/build_literature.py
python3 tools/capacity_model.py
python3 tools/check_preflight.py
```

运行后在 `results/` 生成容量与预算CSV；结果是**假设下的规划计算，不是机器人实验**。论文PDF及下载记录见 `literature/pdfs/` 和 `literature/download_manifest.json`；若某篇下载失败，原文链接仍在阅读库中。
